二、各环节详解与注意点

0

类目剪枝 — 官方类目树 ✅已实测

  • 工具：POST /v1/description-category/tree（Seller API，免费），已落表 data/categories-leaf.json（7,363 末级类目，26 一级类目）。
  • 注意：中间层字段是 description_category_id/category_name，末级是 type_id/type_name；Nexscope 的 categoryId 是下划线拼接格式（如 17027494_17027905_92014）。
  • 注意：旧路径 /v2/category/tree、/v3/category/attribute 已 404 下线，正确属性接口是 /v1/description-category/attribute（+ /values）。
1

热销类目四维评分 ✅接口已验证

  • 工具：Nexscope ozon-category-search，实测返回类目总盘（totalSales/totalRevenue/avgPrice）+ bestsellers（月销/价格/评分）。
  • 四维：规模（totalRevenue）× 动销率（sales>0 商品占比）× 头部集中度（top10 营收份额，垄断类不进）× RFBS 份额（fulfillment=RFBS 过滤）。
  • 注意：ozon-category-products（按俄语路径查）深层路径实测返回 0，用 categoryId 方案替代。
  • 成本：每类目 1 次调用（13–32 credits），全扫 7,363 类目需 10–23 万 credits 超出 Starter 月额（3 万）——必须先剪枝再扫描。
2

关键词漏斗 ✅已跑通

  • 工具：Nexscope market-keyword-search（43 字段，含 queryCn 中文翻译），脚本 select_products.py。
  • 六维+四新闸门（阈值均为初始值，500 词样本后重校准）：
    闸门阈值说明
    月搜索量≥ 5,000需求基本盘
    30 天增长≥ -5%允许微跌，排除跳水
    竞争商品数≤ 3,000拥挤度
    均价带700–5,000₽下沿从 300 上调：低价毛利被头程+佣金吃穿（realFBS 单位经济）
    跨境可售crossBorderSellable=true⭐硬闸门：类目能卖≠跨境能卖
    重量≤ 2kg（体积重 ≤3kg）RFBS 运费结构推断
    加购转化 ca≥ 类目中位数需求质量（相对判据）
    集中度 conversionSharing≤ 0.4头部垄断的词不进
    退货取消率≤ 20%已知风险
  • 产出：候选词 + 爆款商品（ozonId/sku/主图URL）→ 直接生成 1688 图搜任务清单。
3

商品体检（找货前必做）⚠️待实现

  • 工具：Nexscope ozon-product-trend（任意 SKU 的 T-1 日级 price/sales/balance/rating 序列）。
  • 拦什么：促销脉冲（单日暴涨后归零）、假动销、评分 <4.4 的烂卡。
  • 跟卖分支：用 ozon-product-detail 的 modelId 做并入预检——进不了同一合并卡 = 一票否决；卡主可"禁止复制"。
4

单位经济闸门（先算账再花钱）⚠️待实现

  • 位置设计：在 AI 素材投入之前——一张卡素材成本 ¥1.5–2，死在利润上的品不该花这个钱。
  • 公式：到手利润 = Ozon 售价 − 1688 拿货价 − 头程运费 − Ozon 佣金 − 支付/汇损 − 预期退货损耗。
  • 纪律：第三方销量数字只作序数（排名）不作基数（算账）——利润测算只用我方成本+官方费率（calculator.ozon.ru）。
  • 实测教训：皂液器 1688 拿货 ¥23，Ozon 头部卖 350₽(≈¥25)——看着美的品可能毛利为负。
5

1688 图搜找货 ✅已跑通（官方通道）

  • 工具：1688 官方 Ocean Gateway skill（next-1688/1688-product-find），AK 走 OAuth（cli.py get_ak）本地 keyring 存储，不需要企业开发者入驻，免费。脚本 sourcing_agent.py。
  • 实测：6 个候选词 5 个找到货源；皂液器 ¥23·已售1万·相似度 0.91；销量排序 sold_desc 严格有效。
  • 返回字段：product_id / title / price / sold_count / supplier / yx_index（严选指数）/ quantity_begin / detail_url / image_url / similarity_score。compare 能力追加：sku_id/sku_title（单 SKU）+ stock_amount（库存）。
  • ⚠️ 相似度阈值不能一刀切：实拍图搜同款 0.85+ 有效；Ozon 精修设计图（黄底大字）搜同款 0.70+ 即可能对——用"相似度+类目一致性"双判据。
  • 全详情缺口：拿不到阶梯价/全 SKU 表/属性参数——但不阻塞（见"十、参数获取策略"）；补齐路径：万邦 item_get（¥0.022–0.05/次）。
  • 备胎：大吉 API（与官方接口同构，¥499/月/千次日）、万邦（¥0.05/次）——供应商做成可替换 adapter。
6

AI 主图+套图 ✅worker已通👤抽检20%（详见 §三）

  • 工具：阿里云百炼 qwen-image-3.0（$0.03/张，1K/2K 同价，参考图 +$0.003/张）。选它的原因：12 国语言文字渲染（俄语卖点套图的决定性优势）+ 支持 3:4。
  • Ozon 图片硬要求（后台原文实锤）："请上传 3:4 格式的照片，这是所有类别推荐的比例"；≥900×1200、≤10MB、无第三方水印。
  • prompt 双轨：合规轨（去文字/水印/logo、白底、主体居中 ~80%）+ 本地化轨（俄式审美：写实、功能直给、信息密度高）。prompt 模板按类目分文件维护（prompts/），每版记录过审率。
  • ⛔ 人工抽检不可省：AI 图形变/颜色失真会被 Ozon 判"信息不实"——批量前先人工抽检 20%，首 20 张卡全检。
  • 备选：火山方舟 Seedream 4.5（¥0.25/张，图像编辑/参考图保真略强）——接口都是 OpenAI 兼容，换 base URL 即可。

Ozon 上架 ✅链路全验证

  • 链路（全部 endpoint 实测存在）：
    /v1/description-category/tree → /v1/description-category/attribute（字典值必须映射 dictionary_value_id，禁自由文本）→ /v3/product/import（≤100卡/次，异步 task_id）→ /v1/product/import/info（轮询）→ /v1/product/pictures/import（全量覆盖语义：传 1 张会删掉之前 10 张！）→ 价格 /v1/product/import/prices + 库存 /v2/products/stocks
  • 跟卖：/v1/product/import-by-sku 或后台"复制现成商品"入口（已实锤存在）。
  • ⛔ 每日限额（后台实显）：基础 994 + 附加 400，每天最多添加 100 张卡、可更改 2,000——铺货节奏按此设计；2026-02-24 起商品操作统一限流，超限 429 退避 10–15 分钟。
  • 图片传入：必须是公网可直链 URL——alicdn 图有防盗链，必须先下载转存自家 OSS。
  • 文案：LLM 生成俄语标题（≤200 字符）+ rich-content JSON（先拿同类爆款现卡 JSON 当模板）。

AI 视频（仅爆款）⚠️待接入👤手动挂卡

  • 工具：阿里百炼 wan3.0-video（720P ¥0.6/秒，原生带音效/台词/BGM，最长 30s）——与图片同账号同 key，架构收敛。
  • 触发条件：上架后跑 3–7 天数据，出单/转化达标才做——视频永远不进主链路。
  • 做法：AI 主图（OSS URL）→ 图生视频（prompt 只写动作+声音，画面跟随首帧）→ 下载立即转存 OSS（链接有时效）→ 👤后台"媒体"步骤手动挂卡（API 挂法未验证，首张 PoC 时确认）。
  • 成本：10s@720P = ¥6/条；月 10 条爆款含重试 ≈ ¥120/月。

三、AI 生图规则与提示词体系（2026-11-08 实测定稿）

3.1 核心结论：Ozon 热卖主图是“轻信息图”，不是白底图

  • 实拍两个热卖品（皂液器 5928375077 / 壁挂架 5952052737）完全同构：场景底图（浅景深暖调家居）+ 商品占 55–65% + 顶部 2–5 词俄语大标题 + 4–6 个图标卖点阵列；
  • 品类规律：小电器堆参数数字（2000 мА·ч / 10·20·30 мл），家居品讲安装便利+情感（免打孔 / 3 秒安装 / 手写体一句情感点）；
  • 矛盾裁决：白底派（妙手 2026-04）vs 信息图派（实测+极掌 ERP+WBGen 换图后 CTR 翻倍）→ 信息图胜出；白底单品图降级为套图第 2 位。

3.2 官方规则边界（过审红线）

  • 3:4，≥900×1200（小字建议 1200×1600），≤10MB；8 图 + 1 视频 = 内容分 45 满分组合；
  • 主图允许特征与属性图标；四边留白 ~8%（平台会在边缘放角标）；
  • ⛔ 禁（所有图）：价格/折扣/联系方式/社交链接、价值判断词（хит/лучший/новинка）、已售数量、呼吁行动、酒类、3D 草图、黑白照、居家随手拍。

3.3 套图 slot 结构（8+1）

slot角色画面文案
1封面主图（信息图）真实场景，商品 55–65%，顶部预留 22% 标题区2–5 词标题 + 3–4 图标卖点
2白底单品纯白底，商品 80%无文字
3核心卖点图商品 45–55%，简洁渐变底3–6 词大标题 + 数字徽章
4使用演示手部/真人入镜（翻车则改无手版）≤5 词短句，可手写体
5场景延伸第二使用场景≤1 句
6细节/材质近景特写1–3 词材质关键词
7规格/尺寸正视图+蓝图式标注线尺寸数字（数据来源见下）
8适用场景条多场景图标排Подходит для: A / B / C
+1视频封面同主图风格视频 8–30s（仅爆款）

3.4 俄语文案规则（LLM 填占位符时必须遵守）

  • 2–5 词、数字优先（2000 мА·ч 而非“大电池”）；名词/动词短句，禁机翻长句；
  • ⛔ 禁忌词表（机械校验，见 3.6）：хит/лучший/новинка/скидка/цена/акция/купить/бесплатно/%；
  • 手写体只给一句情感点（≤3 词）；适用场景条格式固定 Подходит для: A / B / C。

3.5 文字双轨制（西里尔实测结论）

  • 实测（2026-11-08 皂液器 slot1）：qwen-image-3.0 渲染俄语小字全对、大字标题出现字母级错误（дозатор→дозаіор，л→і）；
  • 对策：AI 画场景底+商品+图标阵列（实测稳定）；大标题/副标题用本地 PIL 贴字（Manrope/Inter Bold，西里尔支持完整，零错误零成本）；
  • prompt v2 改法：主图模板不再让 AI 渲染标题，改为“顶部预留 22% 空白”，生成后 text_overlay.py 叠加。

3.6 content_agent：类目理解 → 套图规格（已验证）

  • 类目不靠 LLM 猜：关键词 API 的 categoryId → 官方类目树机械查表得俄语路径（如 Дом и сад/…/Дозатор для жидкого мыла）；
  • 类目风格库（人工锚点）：一级类目 → 允许的场景白名单 + 文案风格，LLM 只能在约束里选；
  • LLM（qwen-plus，temp 0.4）产出 content spec JSON：ozon 标题 + 每 slot 的场景/文案/动作；
  • 机械校验兜底：① 禁忌词扫描 ② 文案 ≤12 词 ③ 数字溯源——spec 里每个数字必须能在 1688标题/竞品属性找到出处（实测抓获 LLM 编造的“3 秒安装”和“18×9×7cm”）→ 任一命中则 need_confirm=true 进人工确认；
  • 模板文件（git 版本管理）：prompts/slot1_main_infographic_v1.txt、slot2_white_bg_v1.txt、slot3_selling_point_v1.txt、slot4_usage_v1.txt、slot6_detail_v1.txt、slot7_size_v1.txt；俄语文案全部 {{COPY_*}} 占位符，不写死。
详细证据链见 docs/ozon-image-prompt-research.md（两商品逐图拆解 + 规则多源转引 + 矛盾裁决）；实现见 content_agent.py / image_worker.py。

九、全自动化架构（一键运行，仅图/视频两道人审）

状态机（唯一事实源）

pipeline.db（SQLite）：discovered→scored→sourced→checked→profitable→imaging→【待审】→listed→syncing→winning→videoing→【待审】→done。唯一键 = 1688商品ID + Ozon SKU，任何环节崩溃可续跑。

两个审核闸的位置（人工界面只有一个：本地审核台）

闸位置按钮语义
👤图审上架前：imaging→【待审】→listed通过=进上架队列；打回=换 seed 重生（$0.03/张）；毙品=记录死因反哺阈值
👤视频审上架后：winning 之后才生成，独立于主链路通过=挂卡；不过=该品保持无视频在架

三个“隐藏人工点”的对策

  • 新类目属性映射首验：进“类目首验队列”，首 3 张卡人工扫一眼，通过后该类目转全自动；
  • 供应商异常：涨价 >10% 自动重算利润→负毛利自动下架；断货自动清零 Ozon 库存（防超卖），回货自动恢复——规则化，不依赖人；
  • 凭证续期（AK/Ozon key 过期）：每日健康检查 + 通知，月级频率人工。

  • 日限额 100 卡硬顶 · 429 退避 10–15 分钟 · 每日费用上限熔断 · 异常通知（Telegram/邮件）。

十、多 SKU 数据与上架策略

  • 数据通道：万邦 item_get（全 SKU 表+阶梯价，¥0.022–0.05/次）> 开放平台（被卡）> 供应商要规格表；Ocean skill 只给匹配到的单 SKU。
  • 核心认知：自动化上架不需要 1688 全部 SKU——让市场替你选：Ozon 竞品卡反查其在售变体（俄语，市场已验证）→ 取 top 1–3 动销变体 → LLM 模糊匹配回 1688 sku_title（“белый,250мл”↔“P18白色”）+ 变体图相似度二次确认。
  • 上架结构：import items[] 每变体一条，独立 offer_id（{1688商品ID}-{变体序号}）、价格、库存、图片（变体图也走 AI 重制）。
  • 库存同步按变体粒度：cron 刷货源 SKU 库存 → 断货变体自动清零 → 回货恢复。
  • 分期：PoC/M2 只做单 SKU 卡（竞品最热变体）；M3 双变体+映射确认塞进审核台；M4 多变体全自动、滞销变体自动停售。

十二、双视角评审（2026-11-08 第一性原理拷问）

🤖 AI Agent 架构师视角

  • 做对了：workflows over agents——确定性 worker 为主、LLM 只守判断点（选品打分/文案/驳回诊断）；状态机是唯一事实源；人工闸位置正确（不可逆动作前）。
  • 最大缺口：没有 eval 闭环。LLM 属性映射准确率、文案质量目前靠人眼——从第一天起就应把审核台的每次“通过/打回/毙品”记录为评估标签，形成 golden set，否则 prompt 迭代是在盲飞。
  • 次要缺口：决策可追溯性（每品为什么被选/被杀的完整 trace，是数据纪律第三条的落地载体）；prompt 版本管理（阈值有版本了，prompt 也要有）。

🛒 顶级电商运营总监视角

  • 单位经济缺了最大一块：推广费。Ozon 新卡几乎必须投广告起量，CPC 会吃掉 5–15% 毛利——Layer 4 不含广告成本的利润是假利润。必须加“推广准备金”参数（初期按售价 8–10% 预留）。
  • 跟卖模式的结构性矛盾：buy box 由价格指数+时效决定，而 realFBS（15–25 天）自己就是最慢的那个渠道——萌啦的跟卖六条件里“你走快渠道”我们不满足。结论：纯跟卖只适合“现 offer 更慢/缺货”的窗口；跑出数据的 winning 品要规划转 FBP/海外仓，否则跟卖出单≈陪跑。我们的真实定位是“数据驱动铺货”，不是经典跟卖。
  • 改价频率：竞对是小时级自动改价，我们日级同步不够——价格指数掉了会被踢出 buy box。价格监控至少 4 次/日。
  • 节奏风险：新店日更 50 卡太激进（账户权重/审核通过率/迟发率指标），建议 10–20 张高质量卡起步，账户健康指标（取消率/迟发率）进保险丝。
  • 现金流：Ozon 回款周期 + 1688 预付采购 = 营运资金模型缺失，放量前必须算（卖 1 万/月的货要垫多少）。

选品在哪操作？——没有界面。人工唯一动作是编辑 seeds.txt（俄语种子词）并跑 select_products.py；之后 Nexscope 六维漏斗（月搜≥5000 · 增长率≥-5% · 竞争≤3000 · 均价 300–5000₽ · 退货率≤20%）机械过滤。选错的品由下游闸门（unit_econ 判负、图审毙品）杀死，毙品死因反哺阈值——人选品环节不逐个挑品，是方法论评审的定稿决策。

每次点击 = 一条 eval 标签（审核台即 eval 采集器）

👤 点击 通过/打回/毙品→ INSERT reviews(product_id, kind=image, asset_path, decision, prompt_version, decided_at)→ golden set 累积→ prompt 迭代对照 + 阈值重校准（500 词样本后）
设计要点（来自 ROADMAP 缺口③）：没有 eval 闭环，prompt 迭代就是盲飞。所以审核台不是"顺手做个界面"，而是系统闭环的核心部件——它的每次点击都在给 LLM 输出打分。
另两个人工点的形态：类目首验队列（新类目属性映射前 3 张卡扫一眼，过后该类目转全自动）； 视频审（winning 品才生成视频，过=挂卡 / 不过=保持无视频在架，独立于主链路不阻塞）。 凭证过期、429、费用熔断等异常不进审核台，走 Telegram/邮件通知。

# Ozon 后台上架表单字段对齐（seller.ozon.ru）

> 调研日期：2026-11-11。ego-browser 登录 CH 店铺（Fu Mao C）实测
> `/app/products/add/general-info`，类目：住宅和花园 › 家居用品 › 餐具收纳盒
> （description_category_id=17028714, type_id=594158428，与 pipeline id=2 同类目）。
> 点「填写更多」后流程为 4 步：商品信息 → 特征 → 媒体 → 预览。

## 第 1 步：商品信息（listing_worker 必填映射）

| 后台字段 | 必填 | API 字段 / 项目来源 | 注意 |
|---|---|---|---|
| 名称 | 否 | name | 只有卖家可见；**买家看到的名称由模板引擎自动生成**（类目+型号+属性拼接） |
| 类目和类型 | * | description_category_id + type_id | spec `_meta.categoryId` 解析 |
| 条形码 | 否 | barcode | FBP 工作模式及丢失赔偿必备 |
| 货号 | * | offer_id | 建议 `{query}-{offer_id}` |
| 最高价格，¥ | * | price（CNY） | pricing.calc 输出的 price_cny |
| 划线价，¥ | 否 | old_price（CNY） | pricing.calc 的 old_price_cny |
| 包装长度/宽度/高度，**毫米** | * | dimension depth/width/height | **编辑器存 cm，import 需 ×10** |
| 含包装重量，克 | * | weight | 编辑器 weight_g 直接用 |
| 图片 | 是 | images | 3:4 推荐，其他比例自动拉伸/加边框 |

另有「创建一个变体 / 创建多个变体」单选：多变体合并为一张商品卡片。
V1 单 SKU → 选「创建一个变体」。

## 第 2 步：特征（该类目实测 21 个属性）

必填仅 2 个：**品牌 #85***、**型号名称 #9048***（用于合并商品卡片）。
其余：存货类别 #8021、商品重量克 #4383、统一计量单位商品数量 #23249、
#主题标签 #23171、简介（AI 生成营销文本）、组合成类似产品 #22390、
高度厘米 #8414、长度厘米 #8415、宽度厘米 #8416、层数 #6403、安装干燥机 #21699、
每包数量 #8513、材料 #6383、商品颜色 #10096、颜色名称 #10097、保证 #10400、
原产国 #4389、配套 #4384、原厂包装数量 #11650、欧亚经济联盟 HS 编码 #22232、
需要标记代码 #23536（checkbox）。

**API 对齐结论**：后台 21 个属性全部在 `/v1/description-category/attribute`
返回中（该类目共 34 个）。API 有而后台未显示的 12 个（4180 名称、4191 简介、
8229 类型、4497 含包装重量、8789/8790 PDF 等）属旧版/隐藏字段，
其中 8229 类型为 required，import 时建议一并提交（值=类型名）。

## 审核台编辑器对齐实现（2026-11-11）

- `ozon_client.get_attributes` 返回全量属性（含可选/多值），缓存 v2。
- 编辑器④改为**固定白名单**（`EDITOR_ATTR_IDS`，2026-11-11 按后台截图批注定）：
  必填 3 项（品牌/型号/类型）+ 主题标签、商品净重、组合类似品、每包数量（默认 1）、
  商品颜色、颜色名称、长度/宽度（筛选）、配套、原产国、原厂包装数量（默认 1）、
  HS 编码，共 15 项；其余属性一律不显示（早期「更多属性」折叠区已删）。
- shortcut: 多值属性（is_collection）只支持单值输入，多变体场景再升级多选。
